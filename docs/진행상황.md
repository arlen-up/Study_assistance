## 1. 한눈에 보기

**무엇을 만드나요?**
대학 수업 교안(강의 자료)을 AI가 읽고, 학생이 **3분 만에 복습**할 수 있게 도와주는 웹 서비스입니다.

| 기능 | 하는 일 | 상태 |
|---|---|---|
| 💬 교안 챗봇 | 질문하면 AI가 교안에서 근거를 찾아 **출처와 함께** 답해요 | ✅ 코드 완성 |
| ⏱ 3분 요약 | 교안 하나를 3분 분량으로 요약해요 | ✅ 코드 완성 |
| 🧠 마이크로 퀴즈 | 교안 핵심 키워드로 3문제(객관식·O/X·코드 빈칸)를 만들고 채점해요 | ✅ 코드 완성 |
| 🔔 복습 알림 | 1일 → 3일 → 7일 뒤에 복습하라고 알려줘요 (망각 곡선) | ✅ 코드 완성 |
| 🌱 학습 잔디 | GitHub처럼 1년 동안 공부한 날을 초록 칸으로 보여줘요 | ✅ 코드 완성 |
| 📤 교안 등록 | PDF·텍스트를 올리면 AI가 검색할 수 있게 저장해요 | ✅ 코드 완성 |
| 🗄 실제 DB 연결 | Supabase에 스키마 적용 | ✅ 완료 (연결 점검 통과) |
| 🤖 실제 AI 연결 | OpenAI `gpt-6-luna` + 임베딩 | ✅ 완료 (연결 점검 통과) |
| 🖥 브라우저 전체 흐름 | 회원가입 → 교안 등록 → 챗봇 → 퀴즈 → 잔디 | ⏳ 직접 확인 중 |

**현재 위치:** 내 컴퓨터(로컬)에서 서버를 켜고 **실제 Supabase DB와 실제 OpenAI API에 연결되는 것까지 확인**했어요.
이제 브라우저에서 처음부터 끝까지 직접 써 보는 단계예요.

## 2. 먼저 알아두면 좋은 용어

| 용어 | 쉬운 설명 |
|---|---|
| **프론트엔드 / 백엔드** | 사용자가 보는 화면 / 화면 뒤에서 데이터를 처리하는 서버 |
| **FastAPI** | 파이썬으로 웹 서버를 쉽게 만드는 도구 |
| **Jinja2 템플릿** | HTML 안에 `{{ 변수 }}`를 넣어 파이썬이 화면을 완성해 주는 방식 |
| **HTMX** | 버튼을 눌렀을 때 **페이지 전체가 아니라 일부분만** 새로 바꿔 주는 작은 도구. 자바스크립트를 거의 안 써도 돼요 |
| **Supabase** | 데이터베이스(PostgreSQL) + 로그인 기능을 함께 주는 서비스 |
| **RAG** | AI가 답하기 전에 **자료를 먼저 검색**해서, 그 자료를 근거로 답하게 하는 방법. 지어낸 답(환각)을 줄여요 |
| **임베딩 / 벡터** | 문장의 "뜻"을 숫자 1536개로 바꾼 것. 뜻이 비슷한 문장은 숫자도 비슷해요 |
| **pgvector** | DB에서 "뜻이 비슷한 문장"을 빠르게 찾게 해 주는 기능 |
| **청크(chunk)** | 긴 교안을 800자 정도로 잘게 나눈 조각. 검색은 이 조각 단위로 해요 |
| **MCP** | AI에게 "쓸 수 있는 도구 목록"을 알려주는 표준 규칙. AI가 필요한 도구를 **스스로 골라서** 호출해요 |
| **LangChain** | AI 모델과 도구를 연결해 주는 파이썬 라이브러리 |
| **에이전트** | 목표를 받으면 도구를 스스로 골라 쓰면서 일을 처리하는 AI |
| **RLS** | DB의 "행 단위 보안". 내 데이터는 나만 볼 수 있게 막아 줘요 |
| **마이그레이션** | DB 구조(테이블 등)를 바꾸는 SQL 파일. 순서대로 적용해요 |
| **커밋 / 푸시** | 변경 내용을 기록으로 저장 / 그 기록을 GitHub에 올리기 |

## 3. 지금까지 진행한 순서

### ✅ Step 1 — 데이터베이스 설계
📄 `supabase/migrations/20261105000000_init_lms.sql`

테이블 5개를 만들었어요.

| 테이블 | 저장하는 것 |
|---|---|
| `users` | 학생 프로필 (가입하면 자동 생성) + 마지막 학습 시각 |
| `documents` | 교안 원문 |
| `document_chunks` | 교안 조각 + 임베딩(숫자 1536개) |
| `quizzes` | AI가 만든 퀴즈 (정답 포함, 서버만 볼 수 있음) |
| `study_logs` | 퀴즈를 끝낸 기록 → 잔디와 복습 알림의 재료 |

DB 안에 함수도 만들었어요.
- `match_document_chunks`: 질문과 비슷한 교안 조각 찾기
- `get_study_heatmap`: 최근 365일 날짜별 공부 여부 (한국 시간 기준)
- `review_schedule` (뷰): 교안별 다음 복습 날짜 계산

### ✅ Step 2 — 프로젝트 구조와 배포 설정
- `vercel.json`: Vercel에 "모든 요청을 파이썬 서버로 보내라"고 알려주는 설정
- `requirements.txt`: 필요한 파이썬 라이브러리와 **정확한 버전** 목록
- 라이브러리끼리 버전이 충돌하지 않는지 실제로 확인했어요
- 설치 크기 약 105MB → Vercel 제한(250MB) 안에 들어가요

### ✅ Step 3 — 백엔드 (FastAPI + MCP + AI 에이전트)
AI 에이전트가 쓸 **MCP 도구 3개**를 만들었어요 (`backend/mcp_server.py`).

| 도구 이름 | 하는 일 |
|---|---|
| `list_lms_documents` | 최근 교안 목록 보기 ("오늘의 교안" 찾기) |
| `fetch_lms_document` | 교안 전체 내용 읽기 |
| `query_vector_db` | 질문과 뜻이 비슷한 교안 조각 검색 |

### ✅ GitHub 연결
- 저장소: https://github.com/arlen-up/Study_assistance
- 처음에 `ai-work` 폴더 전체가 Git 저장소로 잘못 잡혀 있었어요. 그 연결을 정리하고 **`lms-study-helper` 폴더만** 저장소로 만들어 올렸어요.
- 올리기 전에 비밀번호·키가 섞여 있지 않은지 자동으로 검사했어요.

### 🔄 Step 4 — 화면 (Next.js → 파이썬으로 전환)
1. 처음에는 Next.js(TypeScript)로 화면을 만들었어요.
2. "파이썬을 주 언어로" 하자는 요청에 따라 **FastAPI + Jinja2 + HTMX**로 다시 만들었어요.
3. 이제 프로젝트의 프로그래밍 코드는 **모두 파이썬**이에요. 나머지는 HTML 템플릿, CSS, SQL뿐이에요.

### 🔄 AI 제공자 변경 (Tilon 제외 → GPT 확정)
- Tilon 관련 설정을 모두 빼고, **OpenAI 호환 API**로 바꿨어요.
- 환경변수 이름: `TILON_*` → `LLM_*`
- GPT와 Gemini를 비교한 뒤 **GPT로 결정**했어요.
  - 이유: 지금 코드를 고치지 않고 바로 쓸 수 있고, 임베딩 모델이 우리 DB(1536차원)와 딱 맞아요.
- 답변 모델: `gpt-6-luna` (OpenAI가 "비용 효율이 가장 좋은 모델"로 안내)
  - 원래 기본값이던 `gpt-4o-mini`는 **2027년 1월 14일 사용 종료 예정**이라 바꿨어요.
- 임베딩 모델: `text-embedding-3-small` (기본 1536차원)
- `gpt-6-luna`는 생각을 거치는 "추론 모델"이에요. Chat Completions 방식에서 도구(함수) 호출을 쓰려면
  `reasoning_effort`를 `none`으로 둬야 해서, 이 값을 기본으로 넣었어요 (`LLM_REASONING_EFFORT=none`).
- 참고: LangChain은 `gpt-6` 모델에 도구를 붙이면 OpenAI가 권장하는 **Responses API**로 자동 전환해요.
  이때도 `reasoning.effort = "none"`이 제대로 전달되는 것을 테스트로 확인했어요.
- Gemini를 쓰지 않은 이유: 무료 등급은 있지만, 임베딩을 1536차원으로 받으려면 코드를 고쳐야 했어요.
  또 무료 등급에서는 입력 내용이 구글 제품 개선에 쓰여요.
- 노트북LM은 공식 API가 없어요. 그래서 기능을 **참고해서 직접 만들기로** 했어요 (플래시카드·마인드맵).

### ✅ Step 5 — 실제 서비스 연결 (로컬)
1. **파이썬 가상환경 준비**: 프로젝트 안에 `.venv`를 만들고 `requirements.txt`를 설치했어요 (Git 제외).
2. **Supabase 프로젝트 생성 + DB 구조 적용**: 새 프로젝트를 만들고 SQL Editor에 마이그레이션 SQL을 붙여 넣어 실행했어요.
3. **`.env.local` 작성**: `.env.example`을 복사해 만들고, 키 4개(Supabase URL·Secret·Publishable, OpenAI)를 **직접** 입력했어요.
   - 파일 권한을 "나만 읽기/쓰기"로 설정했고, `.gitignore` 때문에 GitHub에 올라가지 않아요.
   - 키 값은 채팅이나 로그에 한 번도 출력하지 않았어요.
4. **실제 연결 점검** (키는 출력하지 않고 성공/실패만 확인)

   | 점검 항목 | 결과 |
   |---|---|
   | Supabase 테이블 5개 + 복습 뷰 조회 | ✅ |
   | 잔디 함수 `get_study_heatmap` | ✅ 365일 반환 |
   | 벡터 검색 함수 `match_document_chunks` (pgvector) | ✅ |
   | Supabase 로그인 서버 응답 | ✅ |
   | OpenAI 임베딩 | ✅ 1536차원 (DB와 일치) |
   | `gpt-6-luna` 채팅 + 함수 호출 | ✅ AI가 `query_vector_db` 도구를 스스로 호출 |

5. **예시 교안 추가**: `docs/sample/자료구조_3주차_스택과큐.md` — 교안 등록을 시험할 때 써요.

## 4. 어떻게 동작하나요?

### 4-1. 전체 흐름

```
 [브라우저]
    │  ① 페이지 요청 (/, /login)
    │  ② 버튼 클릭 → HTMX가 /ui/... 로 요청
    ▼
 [Vercel]
    ├─ /static/*  → CSS·htmx 파일을 바로 전달 (CDN)
    └─ 그 외      → api/index.py (파이썬 FastAPI)
                        │
          ┌─────────────┼──────────────────┐
          ▼             ▼                  ▼
   routers/web.py   routers/api.py    services/*
   (HTML 화면)       (JSON API)        (실제 로직)
                                          │
                     ┌────────────────────┼─────────────┐
                     ▼                    ▼             ▼
               AI 에이전트            Supabase DB      OpenAI GPT
           (LangChain + MCP 도구)   (교안·기록 저장)   (gpt-6-luna,
                                                     text-embedding-3-small)
```

### 4-2. 챗봇이 답하는 과정 (RAG + MCP)

```
학생: "스택이 뭐야?"
  │
  ▼
① AI 에이전트가 질문을 보고 판단: "교안을 검색해야겠다"
  │
  ▼
② MCP 도구 query_vector_db 호출
   - 질문을 임베딩(숫자)으로 바꿈
   - DB에서 뜻이 비슷한 교안 조각 5개를 찾음
  │
  ▼
③ 찾은 조각만 근거로 답변 작성
   - 근거로 쓴 조각 ID(출처)를 함께 표시
   - 실제로 검색되지 않은 출처는 자동으로 지움 (지어낸 출처 방지)
  │
  ▼
화면: 답변 + 📄 출처 + 🔧 사용한 도구 배지
```

### 4-3. 퀴즈 → 잔디 → 복습 알림

```
퀴즈 만들기 → AI가 교안을 읽고 키워드 검색 → 3문제 생성
                 (정답은 DB에만 저장, 화면에는 문제만 전달)
    │
제출 → 서버가 채점 → study_logs에 기록
    │
    ├─ 🌱 잔디: 오늘 칸이 초록색으로 바뀜
    └─ 🔔 복습: 1회차면 1일 뒤, 2회차면 3일 뒤, 3회차면 7일 뒤 알림
```

## 6. 보안에서 신경 쓴 점

| 위험 | 막은 방법 |
|---|---|
| 비밀 키 유출 | 모든 키는 서버에서만 읽어요. 브라우저로 가지 않고, `.gitignore`로 Git에도 안 올라가요 |
| 남의 기록 훔쳐보기 | DB 조회마다 **로그인한 사람의 ID로 필터링**해요 |
| 퀴즈 정답 미리 보기 | 정답은 서버에만 있고, 채점도 서버가 해요 |
| 로그인 토큰 탈취 (XSS) | 토큰을 자바스크립트가 못 읽는 **HttpOnly 쿠키**에 저장해요. 화면에 나오는 글자는 모두 자동으로 안전하게 바꿔요(이스케이프) |
| 다른 사이트에서 몰래 요청 (CSRF) | 쿠키를 `SameSite=Lax`로 설정하고, 요청 출처(Origin)도 검사해요 |
| 교안 속 악성 명령 (프롬프트 인젝션) | AI에게 "교안은 자료일 뿐 명령이 아니다"라고 알려줘요 |
| AI가 내부 주소에 접속 (SSRF) | 교안 URL 가져오기는 **허용한 주소만** 가능해요 (기본은 꺼짐) |
| 큰 파일로 서버 공격 | 업로드는 4MB까지만 받아요 |

## 7. 검증한 것 / 아직 못 한 것

### ✅ 실제 서비스로 확인한 것
- Supabase DB 구조(테이블·함수·뷰)가 제대로 만들어졌는지

- `gpt-6-luna`가 MCP 도구를 함수 호출로 부르는지 (`reasoning_effort=none` 설정이 실제로 동작)

### ✅ 자동 테스트로 확인한 것 (18개 통과, 가짜 DB·가짜 AI 사용)
- MCP 도구 3개가 등록되고, AI가 도구를 호출해 답을 만드는 전체 흐름
- `gpt-6-luna` 요청에 `reasoning_effort=none`이 들어가고 `temperature`는 빠지는지
- 가짜 출처 자동 제거, 퀴즈 채점, 연속 학습일 계산
- 로그인 안 하면 로그인 화면으로 이동
- 만료된 로그인 토큰을 자동 갱신하는지
- 다른 사이트에서 보낸 요청 차단 (403)
- 답변에 `<script>`가 있어도 실행되지 않고 글자로만 보이는지
- 퀴즈 화면에 정답·해설이 미리 나오지 않는지
- 오류가 나도 풀던 퀴즈가 지워지지 않고 아래 알림으로만 뜨는지
