# 자료구조 3주차 — 스택(Stack)과 큐(Queue)

## 1. 스택(Stack)

스택은 **나중에 넣은 데이터가 먼저 나오는(LIFO, Last In First Out)** 자료구조이다.
책을 쌓아 올린 뒤 맨 위의 책부터 꺼내는 모습을 떠올리면 된다.

### 주요 연산
- `push(x)`: 맨 위(top)에 데이터 x를 넣는다.
- `pop()`: 맨 위의 데이터를 꺼내고 반환한다. 비어 있으면 언더플로(underflow)가 발생한다.
- `peek()`: 맨 위의 데이터를 꺼내지 않고 확인만 한다.
- `is_empty()`: 스택이 비었는지 확인한다.

모든 연산의 시간 복잡도는 **O(1)** 이다.

### 파이썬 구현 예시
```python
stack = []
stack.append(1)   # push
stack.append(2)
top = stack.pop() # pop → 2
```

### 활용 사례
- 웹 브라우저의 **뒤로 가기** 기록
- 텍스트 편집기의 **실행 취소(Undo)**
- 함수 호출 시 사용하는 **콜 스택(Call Stack)** — 재귀가 너무 깊으면 스택 오버플로가 발생한다.
- 괄호 짝 검사, 후위 표기식 계산

## 2. 큐(Queue)

큐는 **먼저 넣은 데이터가 먼저 나오는(FIFO, First In First Out)** 자료구조이다.
은행 창구에 줄을 서서 먼저 온 사람부터 처리하는 모습과 같다.

### 주요 연산
- `enqueue(x)`: 뒤(rear)에 데이터를 넣는다.
- `dequeue()`: 앞(front)의 데이터를 꺼낸다.

파이썬에서 리스트의 `pop(0)`은 O(n)이므로, 큐는 `collections.deque`의 `popleft()`(O(1))를 사용한다.

```python
from collections import deque
queue = deque()
queue.append(1)        # enqueue
first = queue.popleft()  # dequeue → 1
```

### 활용 사례
- 프린터 인쇄 대기열
- 운영체제의 **프로세스 스케줄링**
- 그래프의 **너비 우선 탐색(BFS)**

## 3. 스택 vs 큐 비교

| 구분 | 스택 | 큐 |
|---|---|---|
| 처리 순서 | LIFO (후입선출) | FIFO (선입선출) |
| 삽입 위치 | top | rear |
| 삭제 위치 | top | front |
| 대표 활용 | Undo, 콜 스택, DFS | 대기열, 스케줄링, BFS |

## 4. 정리
- 스택은 한쪽 끝에서만 넣고 빼며, 큐는 한쪽으로 넣고 반대쪽으로 뺀다.
- 두 자료구조 모두 기본 연산은 O(1)로 구현할 수 있다.
- 깊이 우선 탐색(DFS)은 스택, 너비 우선 탐색(BFS)은 큐를 사용한다.
