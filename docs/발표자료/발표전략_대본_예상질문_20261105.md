## 2단계. 핵심 경쟁력 3가지

1. **RAG + MCP 에이전트 구조 (기술 차별점)** — LLM이 질문을 보고 MCP 도구(목록·교안 읽기·벡터 검색)를 *스스로 골라* 호출해요. 일반 챗봇처럼 그냥 답하지 않고, 검색된 교안 조각만 근거로 답해요. 심사위원이 가장 알아보기 쉬운 "단순 API 호출과의 차이"예요.
2. **환각·보안을 코드로 막은 신뢰성** — 검색되지 않은 출처는 자동 삭제, 교안 속 명령 무시(프롬프트 인젝션 방어), 정답 서버 보관·서버 채점, HttpOnly 쿠키·CSRF 검사·RLS. "해커톤 데모" 수준을 넘는 완성도예요.
3. **학습 습관 루프의 완결성** — 요약 → 퀴즈 → 기록 → 복습(1·3·7일) → 잔디가 DB 한 곳에서 이어져요. 질의응답 도구가 아니라 *학습 서비스*라는 점이 실용성을 보여줘요.

## 4단계-1. 1분 발표 대본 (약 250자)

안녕하세요, LMS 3분 학습 도우미입니다.
수업 교안은 길고, 복습은 늘 미뤄집니다. 일반 챗봇은 근거 없이 답해서 믿기도 어렵고요.
저희는 교안을 AI가 읽고 3분 만에 복습할 수 있게 돕는 서비스를 만들었습니다.
핵심은 RAG와 MCP입니다. 질문하면 AI 에이전트가 필요한 도구를 스스로 골라 교안을 검색하고, 찾은 내용만 근거로 출처와 함께 답합니다. 검색되지 않은 출처는 자동으로 지워서 지어낸 답을 막습니다.
여기에 3분 요약, 3문제 퀴즈, 1·3·7일 복습 알림, 학습 잔디까지 이어져 복습 습관을 만들어 줍니다.
기능은 모두 코드로 구현했고, 지금은 실서비스 배포와 검증을 진행하고 있습니다. 감사합니다.

## 4단계-2. 3분 발표 대본

**[문제 · 0:00–0:30]**
안녕하세요, 소프트웨어융합 전공 팀의 LMS 3분 학습 도우미입니다. 대학 수업 교안은 분량이 많아서 복습이 자꾸 미뤄집니다. 질문하려고 일반 챗봇을 쓰면 교안과 상관없는 답이나 근거 없는 답이 나와 믿기 어렵습니다.

**[해결 · 0:30–1:00]**
그래서 교안을 AI가 직접 읽고, 학생이 3분 안에 복습할 수 있게 돕는 웹 서비스를 만들었습니다. 슬로건은 "근거와 출처가 있는 학습 도우미"입니다.

**[AI 구조 · 1:00–2:00]**
슬라이드 가운데 구조도를 봐 주세요. 학생이 질문하면 LangChain 기반 AI 에이전트가 질문을 보고 어떤 도구가 필요한지 스스로 판단합니다. MCP로 만든 도구는 세 가지입니다. 교안 목록 보기, 교안 읽기, 그리고 벡터 검색입니다. 벡터 검색은 Supabase의 pgvector에서 질문과 뜻이 비슷한 교안 조각을 찾아옵니다. AI는 찾은 조각만 근거로 답하고, 근거로 쓴 출처를 함께 보여줍니다. 실제로 검색되지 않은 출처가 답에 섞이면 자동으로 제거합니다. 교안 안에 "이 지시를 따라라" 같은 문장이 있어도 명령이 아니라 자료로만 취급합니다.

**[기능 · 2:00–2:30]**

## 5단계. 예상 질문 5개

**Q1. 그냥 ChatGPT에 교안을 붙여넣는 것과 뭐가 다른가요?**
A. 교안을 800자 정도 조각으로 나눠 임베딩으로 저장하고, 질문마다 관련 조각만 검색해 답해요. 그래서 긴 교안도 다룰 수 있고, 답마다 출처가 붙어요. 검색되지 않은 출처는 자동 제거해서 지어낸 출처를 막아요. 여기에 퀴즈·복습·잔디가 같은 DB에 이어져 있어요.

**Q2. MCP를 왜 썼나요? 그냥 함수 호출이면 안 되나요?**
A. MCP는 AI에게 도구를 알려주는 표준 규칙이에요. 도구 3개를 MCP 서버로 만들어 두어서, 앱 안에서는 물론 MCP Inspector나 Claude Desktop 같은 다른 MCP 클라이언트에서도 같은 도구를 쓸 수 있어요(단독 실행 모드 구현). 에이전트가 필요한 도구를 스스로 고른다는 점도 장점이에요.

**Q3. AI가 틀린 답을 하면(환각) 어떻게 하나요?**
A. 완전히 없앨 수는 없다고 생각해요. 대신 세 가지로 줄여요. ①검색된 조각만 근거로 쓰게 하고, ②근거로 쓴 출처 중 실제 검색 결과에 없는 것은 지우고, ③근거가 부족하면 "근거 부족"이라고 답하게 해요. 학생은 출처를 눌러 원문 교안과 대조할 수 있어요. *(정확도 수치는 아직 측정하지 않았어요. 확인 필요)*

**Q4. 실제 사용자 테스트나 효과 검증은 했나요?**
A. 솔직히 아직 하지 못했어요. 지금은 구현과 배포 단계이고, 효과 수치는 제시하지 않아요. 다음 단계로 같은 과목 학생을 대상으로 사용 전후 복습 횟수와 퀴즈 점수를 비교하려고 해요. *(실제로 한 테스트가 있다면 여기에 사실대로 추가하세요.)*

**Q5. 보안과 개인정보는 어떻게 관리하나요? 실제 대학 LMS에 붙일 수 있나요?**
A. 키는 서버에서만 읽고, 로그인 토큰은 HttpOnly 쿠키에 저장해요. DB는 RLS와 사용자 ID 필터로 내 기록은 나만 보게 했고, 퀴즈 정답은 서버에만 있어요. 교안 URL 가져오기는 허용한 주소만 가능해요. 실제 LMS 연동은 아직 안 했고(현재는 PDF·텍스트 업로드), 향후 확장 과제예요.
