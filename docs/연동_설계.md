# 🔑 학교 시스템 연동 설계 — 학생별 학교 계정 연결 (OAuth 2.0 + PKCE)

> LSSA(Study Overflow)가 학교 LMS(코스모스)·학사정보와 **학생마다 따로, 안전하게** 연결되는 방법을 정리한 문서예요.
> 지금은 학교 허가 전이라 **가상 코스모스**(`lms_mock/`)로 같은 흐름을 끝까지 시연해요.

---

## 1. 왜 바꿨나요 — 예전 구조의 취약점

| 예전 | 문제 |
|---|---|
| "학교 계정 연결" 단추를 누르면 서버가 **본인 확인 없이** 가상 학생을 만들어 연결 | 실제 학교라면 **아무나 남의 학번으로** 연결할 수 있는 구조 |
| 서버 키 `LMS_API_KEY` 하나로 **아무 학생의 토큰이나** 발급(`/api/students/{id}/ws-token`) | 서버 키 하나가 새면 **전교생 데이터**가 샘 (만능 키) |
| 토큰 = `HMAC(서버 키, 학생 ID)` 계산값 | **폐기할 수 없고**, 권한 범위도 없음 |

## 2. 지금 구조 — 학생이 학교에 직접 로그인해 동의

```
학생 브라우저                      LSSA 서버                         학교 (가상 코스모스)
    │ ① '학교 계정으로 연결'          │                                     │
    │──────────────────────────────▶│ state·PKCE 만들어 암호화 쿠키에 보관   │
    │◀───── 학교 로그인 화면으로 ──────│                                     │
    │ ② 학번·비밀번호 로그인 + 권한 확인·허용 ───────────────────────────────▶│ (비밀번호는 LSSA에 안 감)
    │◀──────────── ③ 일회용 코드(5분·1회) 를 붙여 LSSA로 돌려보냄 ──────────│
    │──────────────────────────────▶│ state 확인 (쿠키와 같은 사람·같은 요청?)  │
    │                                │ ④ 코드 + client_secret + PKCE verifier ─▶│ 확인 후
    │                                │◀────────── 학생 전용 토큰 (권한·만료) ───│ 해시만 저장
    │                                │ 토큰을 LMS_TOKEN_KEY 로 암호화해 저장    │
    │                                │ ⑤ 매일 Cron: 학생마다 자기 토큰으로 동기화 ─▶│
    │ ⑥ '연결 해제' ─────────────────▶│ 학교에 토큰 폐기 요청 (RFC 7009) ────────▶│
```

| 표준 | 쓰는 곳 |
|---|---|
| **OAuth 2.0 Authorization Code** (RFC 6749) | 학생 동의 → 일회용 코드 → 토큰 |
| **PKCE S256** (RFC 7636) | 코드를 가로채도 verifier 없이는 토큰으로 못 바꿈 |
| **Token Revocation** (RFC 7009) | 연결 해제 시 학교 쪽 토큰 폐기 |
| **Moodle Web Services** | 토큰 형식(32자리)·호출 규격 그대로 → 기존 코스모스 어댑터 재사용 |

### 권한 범위 (최소 권한)

| scope | 할 수 있는 일 | 쓰는 기능 |
|---|---|---|
| `lms.read` | 수강 과목 · 과제·마감 · 강의 자료 · 과목 성적 읽기 | 대시보드, 챗봇, 자료 가져오기 |
| `academic.read` | 내 성적표 읽기 | 졸업까지 남은 학점, 커리어 나비게이터 |
| `lms.submit` | 과제를 '제출 완료'로 표시 | 과제 목록의 '제출 완료' 단추 |

함수마다 필요한 권한을 학교 쪽에서 검사해요 (`lms_mock/moodle.py`의 `FUNCTION_SCOPES`). 허용받지 않은 기능은 `accessexception`으로 거절돼요.

### 무엇을 어디에 저장하나

| 값 | 저장 위치 | 형태 |
|---|---|---|
| 학교 비밀번호 | 학교 DB `lms_students.password_hash` | scrypt 해시 (원문 없음). **LSSA는 받지도 않음** |
| 일회용 코드 | 학교 DB `lms_oauth_codes` | sha256 해시 · 5분 · 한 번만 (`lms_consume_oauth_code`가 확인과 '사용됨' 표시를 한 번에) |
| 학생 전용 토큰 | 학교 DB `lms_access_tokens` | sha256 해시 · 180일 · 폐기 가능 |
| 학생 전용 토큰 | LSSA DB `users.lms_token_enc` | `LMS_TOKEN_KEY`로 암호화 (Fernet: AES + HMAC) |
| state · PKCE verifier | 학생 브라우저 쿠키 `lms_oauth` | 암호화 · HttpOnly · 10분 · 콜백 경로에서만 |

## 3. 막은 공격

| 공격 | 막는 방법 | 확인 |
|---|---|---|
| 남의 학번으로 연결 | 학교 로그인(학번+비밀번호)을 통과해야만 코드 발급 | E2E |
| 서버 키 유출 → 전교생 정보 | 서버 키로는 과목 목록·졸업 요건(학교 공통 정보)만. 개인 정보는 학생 토큰으로만 (`/api/me`) | E2E |
| A 학생 토큰으로 B 학생 정보 | 토큰 = 학생 1명. 학생 ID를 주소로 받지 않음 | E2E |
| 코드를 다른 사이트로 빼돌리기 | 돌아갈 주소는 같은 사이트의 정해진 경로만 | `tests/test_school_oauth.py` |
| 코드 가로채기 | PKCE (verifier 없으면 토큰 못 받음) | 테스트 + E2E |
| 코드 재사용 | 한 번 쓰면 끝 (DB에서 원자적으로 '사용됨' 표시) | E2E |
| 다른 사람이 시작한 연결을 내 계정에 끼워 넣기 | state를 암호화 쿠키(사용자 ID 포함)와 비교 | 테스트 + E2E |
| 허용 안 한 기능 쓰기 | 함수별 scope 검사 | 테스트 + E2E |
| 연결 해제 후에도 계속 읽기 | 학교 쪽 토큰 폐기 → 이후 `invalidtoken` | E2E |
| DB 유출 | 학교: 코드·토큰은 해시만 / LSSA: 토큰은 암호화 | 테스트 |
| 학번이 있는지 떠보기 | "학번 또는 비밀번호가 맞지 않아요" 한 가지 문구 + 없는 계정도 같은 계산 시간 | 코드 |
| 로그인 화면을 다른 사이트 안에 숨기기 (클릭재킹) | `X-Frame-Options: DENY` | 코드 |

## 4. 실제 학교로 옮길 때

| 단계 | 할 일 |
|---|---|
| 1 | 학교 전산팀에 앱 등록 요청 → `client_id`, `client_secret`, 허용 redirect 주소 발급 |
| 2 | 학교 쪽 방식에 맞춤: **OAuth 2.0** 제공 시 그대로 / **LTI 1.3**(교육용 표준)만 제공 시 로그인 부분을 LTI 실행(launch)으로 교체 |
| 3 | 환경변수만 교체: `MOODLE_BASE_URL`(코스모스 주소), `LMS_OAUTH_CLIENT_ID`, `LMS_OAUTH_CLIENT_SECRET` |
| 4 | 학사정보(졸업 요건·전체 성적표)는 LMS와 별개 시스템 → 별도 협의 |

### 학교 협조 전에 쓸 수 있는 보조 경로
- **캘린더 내보내기(iCal) 주소**: Moodle 기본 기능. 학생이 직접 발급한 주소로 **과제 마감일만** 읽을 수 있음 (교안·성적 X)

### 일부러 쓰지 않은 방법
| 방법 | 쓰지 않은 이유 |
|---|---|
| 학번·비밀번호를 받아 대신 로그인(스크래핑) | 비밀번호를 우리가 보관하게 됨, 이용약관 위반 소지, 2단계 인증·계정 잠금 |
| 학교 관리자 토큰 하나로 전교생 조회 | 만능 키 — 하나가 새면 전교생 정보가 샘 |
| 모바일 앱 비공식 API 사용 | 비공식·약관 위반 소지, 예고 없이 바뀜 |

## 5. 시연 방법

| 상황 | 방법 |
|---|---|
| 시연 계정 5개 (`lms-demo1~5@example.com`) | 스크립트가 이미 연결해 둠. 가상 학교 학번 `2026900001~5`, 비밀번호는 스크립트 실행 때 정한 값 |
| 새 계정으로 연결 장면 보여 주기 | 🎓 학점·진로 → **🏫 학교 계정으로 연결** → 가상 코스모스 화면 → **시연용 학생 계정 만들기** → 로그인·허용 |
| 연결 해제 | 🎓 학점·진로 → **연결 해제** (학교 쪽 토큰도 폐기) |

## 6. 확인 기록 (2026-11-06, 실제 Supabase DB)

임시 LSSA 계정 2개와 임시 가상 학생 2명으로 확인하고 모두 지웠어요. **25가지 모두 기대대로** 동작했어요.

| 구분 | 확인한 것 |
|---|---|
| 정상 흐름 | 연결 시작(PKCE S256·state) → 학교 동의 화면(권한 3가지 표시) → 로그인·허용 → 콜백 → 연결 완료, 화면에 학번 표시 |
| 저장 | 학교 DB엔 토큰 해시만, LSSA DB엔 암호화된 토큰만 |
| 로그인 | 틀린 학교 비밀번호 → 코드 발급 안 됨 |
| 코드 | 이미 쓴 코드 재사용 → `invalid_grant` / PKCE verifier 틀림 → `invalid_grant` / 앱 비밀값 틀림 → 401 |
| 주소·요청 위조 | 다른 사이트로 돌아가는 주소 → 오류 화면(돌려보내지 않음) / 남이 시작한 연결(state 다름) → 거절 |
| 학생 분리 | A 토큰 → A 정보만, B 토큰 → B 정보만 / A 토큰으로 B 성적 → 거절 |
| 만능 키 | 서버 키만으로 `/api/me` → 401 / 예전 토큰 발급 주소 → 404 |
| 권한 범위 | 읽기만 허용한 토큰: 과제 제출 → `accessexception`, 성적표 → 403, 수강 과목 → 허용 |
| 해제 | 연결 해제 → 학교 토큰으로 읽기 `invalidtoken`, LSSA 쪽 토큰 삭제 |
| 예전 방식 | 토큰 없이 연결돼 있던 계정 → "다시 연결해 주세요" 안내 |
